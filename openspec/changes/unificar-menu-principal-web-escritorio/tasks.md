# Tareas: unificar menú principal Web y escritorio

## Fase 1 — Inventario y contrato común

- [x] 1.1 Inventariar cada acción actual de los menús Web y Tkinter, sus rutas, atajos, estado de bloqueo y público objetivo.
- [x] 1.2 Definir un catálogo compartido de categorías, etiquetas, descripciones, iconos, orden y equivalencias de acciones antiguas.
- [x] 1.3 Definir la matriz de migración de enlaces, preferencias y atajos.
- [x] 1.4 Añadir especificaciones y pruebas contractuales de paridad Web/Tkinter.
- [ ] 1.5 Validar con docentes o estudiantes que los ocho nombres se entienden sin entrenamiento técnico y ajustar microcopias si procede.

## Fase 2 — Contenido didáctico y navegación principal

- [x] 2.1 Sustituir **Ejemplos** por **Aprender** y agrupar los programas por nivel y tema, con descripciones de aprendizaje.
- [x] 2.2 Sustituir **Escenarios** por **Prácticas guiadas** y mostrar objetivo, mundo y programa antes de cargar.
- [x] 2.3 Reorganizar **Mundos** para distinguir editor, mundo en blanco, importación y preestablecidos.
- [x] 2.4 Mantener **Misiones** como categoría propia y mostrar progreso, propósito y requisitos.
- [x] 2.5 Implementar la estructura y comportamiento equivalente en Web y Tkinter.
- [x] 2.6 Advertir cambios sin guardar antes de sustituir programa, mundo o misión en ambos productos.

## Fase 3 — Preferencias y diagnóstico

- [x] 3.1 Crear **Configuración de simulación** para tema, fidelidad y tiempo máximo, con valor actual, unidad, recomendación e impacto.
- [x] 3.2 Crear **Diagnóstico** para trazas, estado de sesión y exportación, con lenguaje comprensible y acceso en contexto de soporte.
- [x] 3.3 Simplificar **Ayuda** en Aprender, Soporte e Información; conservar el enlace al libro y los destinos existentes.
- [x] 3.4 Aplicar estados de menú coherentes durante ejecución, depuración y error.

## Fase 4 — Confiabilidad de carga

- [x] 4.1 Corregir la carga de ejemplos, mundos, prácticas y misiones cuando la sesión expire o la solicitud falle.
- [x] 4.2 Garantizar actualización atómica de editor, mundo, telemetría y título; mostrar resultado verificable de éxito o error.
- [x] 4.3 Añadir recuperación de sesión y reintento seguro sin perder el trabajo no guardado.
- [x] 4.4 Añadir telemetría de errores de carga sin exponer datos sensibles.

## Fase 5 — Pruebas, accesibilidad y liberación

- [x] 5.1 Pruebas unitarias del catálogo, migración de preferencias y manejo de error de carga.
- [x] 5.2 Pruebas Web end-to-end para cada categoría, teclado, lector de pantalla, menú reducido y estados durante ejecución.
- [x] 5.3 Pruebas manuales Tkinter para cada categoría, atajos, foco, contraste y redimensionamiento.
- [x] 5.4 Prueba comparativa Web/Tkinter: misma acción, mismo resultado y misma terminología.
- [x] 5.5 Actualizar ayuda, manual técnico, capturas y protocolo de validación.
- [ ] 5.6 Registrar evidencia de liberación y archivar la especificación al cerrar.
